# Cómo funcionan las clases

Una carpeta por clase, numerada: `01-primer-programa`, `02-...`.

## Qué hay adentro de cada clase

    NN-tema/
      ENUNCIADO.md    <- lo escribe Claude. Qué hay que lograr y por qué.
      practica/       <- lo escribo YO. Archivos chicos para calentar el tema.
      REVISION.md     <- lo escribe Claude, DESPUÉS de que entregué.

`REVISION.md` no aparece hasta que entrego algo. Que exista significa que esa clase
ya fue corregida, y ahí queda por escrito qué estaba flojo y por qué. Sirve para volver.

## practica/ vs Asistente/

Son dos cosas distintas y conviene no mezclarlas:

- **`Clases/NN-tema/practica/`** — borradores. Pruebo el concepto suelto, rompo cosas,
  escribo mal a propósito para ver qué pasa. **Nada de acá tiene que quedar lindo.**
  No se borra: sirve para ver de dónde vengo.
- **`Asistente/`** — el proyecto de verdad. Código que queda y que voy a usar. Acá sí
  importa que esté bien.

El orden normal de una clase: entiendo el concepto en `practica/`, y recién entonces
lo aplico en `Asistente/`.

## Cómo se cierra una clase

Una clase **no** se cierra porque el código funciona. Se cierra cuando puedo explicar
sin mirar la pantalla por qué está escrito así.
